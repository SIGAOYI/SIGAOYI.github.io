核心定性 01 · 什么是 EIP-7702？

普通钱包（EOA）的“外挂智能合约”机制

以太坊 2025 年 Pectra 升级引入的账户抽象标准（交易类型 0x04）。它允许普通私钥账户（EOA）在不改变自身地址与余额的前提下，向自己的 code 字段写入一段 23 字节的委托指针（0xef0100 || 合约地址）。此后任何人调用该钱包，EVM 都会加载目标合约代码并在该钱包自己的资产上下文中执行（等同于 DELEGATECALL）。

核心定性 02 · 为什么说不是协议漏洞？

十条异构公链同时失守，病根在“签名前”

比特币（UTXO）、Solana/XRP（Ed25519 签名）根本不存在 EIP-7702，却在同一 20 分钟窗口内签发了价值逾 25 亿美元的合法转账。慢雾余弦与 TRM Labs 一致指出：EIP-7702 本身没有任何代码 Bug；攻击者是攻破了币安内部的跨链自动签名调度系统，而 EIP-7702 只是攻击者在以太坊上用来“把上百笔转账合并为 1 笔批量清扫”的加速器。

核心定性 03 · 为什么风控没拦住？

传统审批流只看“转多少钱”，不看“我是谁”

交易所热钱包每日自动签发数千笔提币，HSM/MPC 审批策略主要检查两个字段：收款地址是否在白名单、单笔转账金额（Value）是否超限。然而 EIP-7702 授权交易的转账金额为 0，也不触发 ERC-20 transfer，它改写的是“这个钱包地址挂载什么代码”，从而完美穿透了传统金额风控规则。

💡 深度追问 1：为什么黑客要在单笔交易里塞入整整 50 份授权？

在以太坊中，为了防止“重放攻击（Replay Attack）”，每一份 EIP-7702 授权签名都必须绑定目标钱包当前的交易计数器 nonce。只有当交易上链执行那一刻，授权里的 nonce 与钱包实时 nonce 严格相等，委托才会生效。

但 Binance 14 是币安最繁忙的以太坊热钱包，平均每分钟都在向外处理大量正常用户提币，nonce 处于高速递增状态。这说明攻击者并没有直接拿到裸私钥在本地毫秒级签名，而是通过被渗透的内部签名接口异步导出了签名——为了克服导出签名到广播上链之间的时间差，攻击者一次性让系统预签了 18,914,775 到 18,914,824 共 50 个连续号码，像散弹枪一样打包进同一笔交易，确保必有一发命中实时 nonce！

💡 深度追问 2：为什么早上 06:55 币安在用同一把钥匙救钱，却没撤销委托？

链上数据显示，北京时间 06:55（事发后两个半小时），币安运维人员仍在使用 Binance 14 的私钥将未被黑客列入清扫名单的零碎长尾代币转回安全地址，但直到 08:06（00:06 UTC）才正式撤销 EIP-7702 委托。

原因在于传统交易所应急剧本（Playbook）是围绕“停止充提服务 + 转移残余资产”编写的。在 Pectra 升级之前，普通 EOA 地址的 code 字段永远为空；许多老旧的机构端钱包管理后台甚至没有可视化显示“当前 EOA 是否挂载了 0xef0100 指针”，也没有预设一键发送 address(0) 撤销签名的紧急按钮，导致黑客代码在热钱包上足足裸奔了 3 小时 45 分钟。

🏦 交易所与机构金库（MPC / HSM）四大强制升级铁律

Architecture Remediation
1. 签名策略层默认拦截 Type-0x04

在 HSM/MPC 策略引擎中，严禁热钱包签署任何 EIP-7702（0x04）交易或 0x05 魔数开头的授权摘要；任何连续 Nonce 批量签名请求直接触发全局熔断。

2. 实时监控 EOA 的 Code 字段非空告警

对所有金库与热钱包地址运行区块级 eth_getCode 巡检。一旦普通热钱包返回 0xef0100... 非空字节码，毫秒级冻结充提并广播预签名的 address(0) 撤销交易。

3. 按公链与资金层级物理隔离签名网关

本次十条链在 20 分钟内被一锅端，暴露了“单一提币调度容器统管全链签名请求”的架构缺陷。必须将 BTC、EVM、Solana 的签名审批流与鉴权密钥彻底解耦。

4. 做市商与 DEX Solver 实时黑名单阻断

黑客在被盗数分钟内通过 UniswapX 与 1inch Fusion 向做市商倾销了逾 3.25 亿 USDT。Resolver 节点应接入 TRM Beacon 实时流，自动拒填毫秒级大额黑客脏款订单。

🛡️ 普通链上用户如何防范 EIP-7702 钓鱼？

User Self-Custody Guide
  • 不必恐慌卸载钱包，但严禁盲签未知消息：正如 ZeroDev 创始人 Derek Chiang 所言，EIP-7702 协议本身安全，攻击前提是“诱骗你签下授权”或“盗取你的私钥”。
  • 认准钱包弹窗中的「账户升级 / Delegation」高危警告：主流钱包（MetaMask、Rabby、OKX Wallet）对 EIP-7702 授权均设有专门的强阻断提示；任何空投网站要求你将钱包“委派/升级（Delegate/Upgrade）”给未知合约，100% 是清扫器钓鱼（主网已有超 63% 的 7702 授权指向恶意扫币合约）。
  • 警惕 chain_id = 0 的全链通杀授权：若不慎签署了 chain_id = 0 的 EIP-7702 授权，攻击者可在所有兼容 EVM 链（ETH/BNB/Base/Arb）重放劫持你的同一地址。发现异常请立即使用 Revoke 工具或钱包内置的「取消账户委派（Revoke Delegation）」功能覆盖为 0x0000...0000。
