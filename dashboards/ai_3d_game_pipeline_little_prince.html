阶段 01 · 范围与契约定义 耗时: 1.5 天 (9%)

需求结构化与垂直切片 (Vertical Slice) 契约

拒绝“让模型一次生成一个开放世界”的幻觉。使用 Fable 5.1 / Opus 5.5 梳理 PRD，固化“必须出现清单”（长椅、水壶、基地）与多机位验收标准。

阶段 02 · 空间透视对齐 耗时: 3.0 天 (19%)

2D 概念图多视角解构 (Multi-view 2D)

由主视图衍生俯视图、斜侧透视图与局部材质图；角色生成四视图（正/侧/背/T-pose）。人工卡点校验比例稳定性与主光冲突。

阶段 03 · 网格化与重构 耗时: 3.5 天 (22%)

Tripo 批量 3D 生成与白模拓扑审查

采用 Tripo H3.1 生成复杂异形道具，Smart Mesh P2.0 提取角色网格。坚持“先审白模几何、后贴纹理贴图”，防范隐性结构塌陷。

阶段 04 · 标准化清洗与动捕 耗时: 4.5 天 (28%)

Blender 无头 Python 清理与骨骼/IK 绑定

CLI 脚本自动化应用旋转缩放、居中轴心、清理非流形边。Mixamo 动捕接入，对水壶握持等接触姿态引入反向动力学（IK）修正穿模。

阶段 05 · 状态机装配与闭环 耗时: 3.5 天 (22%)

Unity 场景装配、C# 触发器与多机位盲审闭环

标准化工程目录，C# 轻量触发交互。三机位多视角截图提交给独立 VLM Reviewer Agent 产生局域差异清单，渐进回归打包。

阶段 01 深度拆解 标准约束

需求结构化与垂直切片 (Vertical Slice) 契约

● 核心逻辑：游戏工业里的“垂直切片”（Vertical Slice）指的是集中全部资源，完整打通一段极小但要素齐全的端到端可玩流程，以此验证技术管线与手感，杜绝在全局铺开后才发现系统性缺陷。

● 约束范式：定义 1 个星球地块、1 个角色（待机/走/拾取）、1 个核心道具（水壶浇花交互）与 1 个出口触发器。将这些写死为不可变自然语言契约，贯穿后续全部 Agent 的 Context 提示词。

// 关键验收契约
Scope: Planet Base (3-5 min gameplay)
Must_Have: [Player, Planet_Ground, House, Teapot, Exit_Gate]
Acceptance: 3-Camera View Alignment (Front, Top, Side)

适合单独交付 AI (Tripo) 生成的资产

具备复杂自然曲面、有机造型、丰富高频细节且具备独立语义的离散资产。传统手工建模耗时极长，而 AI 模型可直接根据图纸端到端重构。

  • 小王子主角角色：四视图输入 Smart Mesh P2.0，提取拓扑合理的白模网格与服装配色。
  • 标志性互动道具：水壶、玫瑰花玻璃罩、木质长椅、望远镜、手提箱等异形道具。
  • 自然景观要素：扭曲的猴面包树主干、风化岩石群、独立外星植被单体。
💡 工程经验：资产必须独立命名归档（如 prop_teapot_v01.glb），附带输入图与生成时间戳，严禁多个道具混合生成。

适合在 Blender/Unity 直接搭设的几何基底

具备规则几何结构、严格空间物理拓扑、需要精确行走对齐或充当物理碰撞体的工程基底。交给 AI 生成极易出现歪斜、凹坑与轴向漂移。

  • 地面与球形星球基底：规则多边形网格或球体展平，保证平整可行走，无异常物理颠簸。
  • 建筑外墙、台阶与立柱：标准几何拉伸，精准对齐 1 个标准单位，利于网格拼接。
  • 碰撞体积与触发器 (Colliders & Triggers)：标准 Box/Capsule/Sphere Collider，保证物理碰撞计算极轻量。
⚠️ 避坑原则：“异形找 AI，基准靠引擎”。用最廉价的标准几何体搭骨架，用 AI 生成的精美道具填满血肉。

⚙️ Blender 无头 Python 批处理与接触动作 IK 动态校正

Headless CLI Automation

1. 无头批处理清洗 (Asset Normalization)： Tripo 导出的网格往往存在原点漂移（不在底座几何中心）、尺寸未应用缩放（1.0 比例丢失）或隐藏孤立网格。在服务器端无界面执行 Python 批处理脚本，执行旋转缩放应用（Transform Apply）与中心重设，直接产出符合 Unity 标准的干净 glTF/GLB。

# Blender 无头执行命令
blender --background ./blend/cleanup.blend \
  --python ./scripts/prepare_asset.py
# 核心：bpy.ops.object.transform_apply()
# 自动修正边界中心并导出 glTF

2. 接触动捕的反向运动学 (IK) 修正： Mixamo 下载的基础动作是开环动画。角色拿起水壶时，手掌与水壶把手极易发生穿模或悬空脱手。 通过引入 IK（反向运动学，根据末端手掌把手目标倒推手肘与肩部关节角度），固定接触帧约束，实现手掌与道具牢固吸附、行走时自然跟随。

// 接触点验收四项军规：
1. 抓取起始帧：手掌自然展开对准把手
2. 提握中间帧：IK 链锁定在抓握锚点
3. 移动巡游态：手部跟随摆动不脱钩
4. 释放结算帧：水壶位置与任务事件同步触发

📸 多机位盲审闭环系统 (Multi-Camera Blind Review Loop)

破解 AI 游戏制作中最致命的“单视角好看、换个角度就穿帮”陷阱。由独立审查 Agent 进行差异对比，杜绝无脑全局重构。

机位 A：正面主视图审查反馈 空间吻合度 96%

正面机位主要用于检验场景主视觉构图、光影基调与角色剪影。小王子的围巾流线、地表草坪的色彩饱和度与背景云海深度对齐良好。

审查 Agent 提取之差异清单 (Diff List)：
✓房屋门楣材质反射率与概念图主光源一致。
⚠水壶把手在特定光照角下产生多余高光噪点，需在材质粗糙度通道修正。
💡 核心机制警示：提示词严禁包含“请重新生成整个场景”！审查 Agent 必须只输出局部修改指令（如“仅调整水壶缩放至 0.85，位置沿 Z 轴微调 +0.2m”），避免推翻已稳定的拓扑基座。
